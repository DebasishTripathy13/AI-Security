Microsoft AI security

Microsoft has the most complete public body of AI security work: the Responsible AI Standard, one of the earliest AI red teams, PyRIT, Prompt Shields, Spotlighting, and security products for AI workloads. This matters for any Microsoft or Azure-heavy role, and it's a useful reference architecture anywhere.

⏱ 25 minPriority ★★★ (★★★★ if interviewing at Microsoft or an Azure shop)
Key takeaways
  • Responsible AI principles plus four mitigation layers: model, safety system, system message & grounding, UX.
  • Prompt Shields (user + document attacks), Spotlighting and groundedness detection are the core content controls.
  • Defender for Cloud (AI threat protection, AI-SPM), Purview DSPM for AI, Entra Agent ID and the APIM AI gateway cover runtime and governance.
  • Copilot's biggest risk is usually oversharing. EchoLeak shows classifiers need deterministic backups.

Responsible AI: principles and process

6 principles

  1. Fairness
  2. Reliability & Safety
  3. Privacy & Security
  4. Inclusiveness
  5. Transparency
  6. Accountability

Mnemonic: "FRP-IT-A".

Responsible AI Standard v2 (2022)

Turns the principles into concrete goals and requirements for product teams: impact assessments, sensitive-use reviews, data and fairness requirements, human oversight, transparency documentation. It's overseen by the Office of Responsible AI.

The practice loop

Microsoft frames RAI work as Govern → Map → Measure → Manage, aligned to NIST AI RMF: identify harms (red teaming), measure them (evaluations), mitigate them (layers), and operate (monitoring).

Mitigation layers Microsoft describes for GenAI apps: (1) Model: choose the right model and fine-tune; (2) Safety system: content filters, Prompt Shields, abuse monitoring; (3) System message and grounding: metaprompt design, RAG; (4) User experience: disclosure, citations, human review, feedback. Interviewers like hearing these four layers.

The Microsoft AI Red Team

  • Formed in 2018 as one of the first dedicated AI red teams. It red-teams models and products before release, covering both security and RAI harms.
  • Open-sourced Counterfit (2021, classic ML) and then PyRIT (2024, GenAI). See module 10.
  • Co-created the Adversarial ML Threat Matrix with MITRE (2020), which became ATLAS.
  • Published "Lessons from red teaming 100 generative AI products" (Jan 2025). The 8 lessons are in module 10.
  • Disclosed jailbreak techniques such as Crescendo (multi-turn, 2024) and Skeleton Key (2024).
  • Co-ran the LLMail-Inject adaptive prompt-injection challenge (2024–25), where participants attacked a simulated email assistant protected by various defenses.

Failure-mode taxonomies

Failure Modes in Machine Learning (2019)

Intentional failures (attacks): perturbation/adversarial examples, poisoning, model inversion, membership inference, model stealing, reprogramming, physical-domain adversarial examples, malicious ML provider recovering training data, ML supply chain attacks, backdoors, exploiting software dependencies.

Unintentional failures: reward hacking, side effects, distributional shift, natural adversarial examples, common corruption, incomplete testing.

Taxonomy of Failure Modes in Agentic AI Systems (Apr 2025)

Splits failures into novel vs existing, each in security and safety pillars. Novel security failures include agent compromise, agent injection, agent impersonation, agent flow manipulation, multi-agent jailbreaks. Existing risks amplified by agents include memory poisoning, cross-domain prompt injection, HITL bypass, incorrect permissions, excessive agency, resource exhaustion.

Case study: an autonomous email agent's memory was poisoned by one crafted email instructing it to forward certain messages, and it then did so. Mitigations: memory write controls, authenticated memory, and treating email content as untrusted.

Severity: Microsoft's AI vulnerability classification

MSRC publishes a Vulnerability Severity Classification for AI Systems (the "AI bug bar") used for its AI bounty. It groups AI-specific vulnerabilities into:

CategoryExamples
Inference manipulationPrompt injection (direct and cross-prompt/XPIA), input perturbation, causing the model to take unintended actions or produce manipulated output
Model manipulationModel poisoning, data poisoning during training or fine-tuning
Inferential information disclosureMembership inference, attribute inference, training data reconstruction, property inference, model stealing, prompt (system instruction) extraction, extraction of other users' inputs

Severity (Critical / Important / Moderate / Low) depends on impact. Cross-user data exfiltration or unauthorized actions without user interaction rate higher. Classic web vulns in AI products are rated with the normal bug bars.

Interview nuancePrompt Shields is a classifier, so it's probabilistic. EchoLeak (2025) bypassed M365 Copilot's XPIA classifier by phrasing the malicious email as if it were addressed to a human. That's why Microsoft also invests in deterministic controls: link and image restrictions, CSP, permissions, and Spotlighting.

Spotlighting

Spotlighting (Hines et al., Microsoft, 2024) is a family of prompt-engineering techniques that help the model tell untrusted input apart from instructions. Microsoft reported that it cut indirect-injection attack success from over 50% to under 2% in its experiments, with little effect on task quality.

Microsoft Foundry (Azure AI Foundry): build-time controls

Guardrails and controls

  • Configurable content filters per model deployment (input and output); Prompt Shields; blocklists
  • Network isolation (managed VNet, private endpoints), managed identity, customer-managed keys
  • Azure OpenAI data handling: prompts and completions aren't used to train foundation models; abuse monitoring with limited retention and an approved opt-out path
  • Model catalog with model cards; models are scanned before being offered

Evaluations and testing

  • Quality evaluators: groundedness, relevance, coherence, fluency, similarity
  • Safety evaluators: hateful/unfair, sexual, violent, self-harm, protected material, indirect-attack jailbreak, code vulnerability
  • Agent evaluators: intent resolution, tool-call accuracy, task adherence
  • AI Red Teaming Agent (PyRIT-based) scans with ASR scorecards
  • Tracing via OpenTelemetry for agent runs

Secure Azure GenAI reference architecture

Microsoft 365 Copilot security model

  • Copilot accesses content through Microsoft Graph with the signed-in user's permissions. It can only surface what the user could already open.
  • The flip side: oversharing becomes discoverable. Files shared with "Everyone" that nobody ever found are now one question away. Fixes: SharePoint Advanced Management (site access reviews, restricted content discovery), Purview sensitivity labels and DLP, and least-privilege sharing.
  • Prompts, responses and Graph data aren't used to train the foundation models, and processing stays within the Microsoft 365 service boundary.
  • EchoLeak (CVE-2025-32711) showed the residual risk: content the user receives (email) is untrusted input that can steer Copilot. Microsoft patched it server-side, and the lesson is to combine classifiers with deterministic output restrictions.
  • Copilot Studio agents: authenticate with user credentials where possible, restrict connectors with DLP policies, review agent sharing, and monitor with Defender and Purview.

Microsoft-specific interview soundbites

On defense in depth"Microsoft's guidance layers mitigations at the model, the safety system, the system message and grounding, and the UX. I'd add identity and tool authorization as the deterministic layer underneath, because Prompt Shields lowers injection rates but EchoLeak showed classifiers can be bypassed."
On Copilot rollouts"The biggest Copilot risk is usually oversharing, not the model. Copilot respects permissions, so before rollout I'd run Purview DSPM for AI and SharePoint access reviews, label sensitive content, and apply DLP so labeled files can't be processed."
On red teaming"I'd use PyRIT, or the Foundry AI Red Teaming Agent built on it, to automate scale (encodings, multi-turn Crescendo, XPIA payloads), and keep humans on business-logic abuse. Each finding becomes a regression test with an ASR threshold in the pipeline."
