Design rules

Principles to repeat

  • The LLM is not a security boundary. Model proposes, code decides.
  • Everything in context is untrusted (docs, web, email, tools, memory, agents).
  • Lethal trifecta: private data + untrusted content + external comms → exfiltration.
  • Rule of Two (Meta): at most 2 of [untrusted input, sensitive access, state change / external comms] without HITL.
  • Least agency: minimal tools, scopes, autonomy.
  • User-scoped, short-lived tokens (OBO); no secrets in prompts.
  • Risk-tiered HITL; beware approval fatigue.
  • Deterministic controls for guarantees; classifiers for noise reduction.

Injection-resistant patterns

  • Action-Selector: fixed actions, no feedback
  • Plan-Then-Execute: plan before reading untrusted data
  • LLM Map-Reduce: isolated sub-agents per item
  • Dual LLM: privileged planner + quarantined reader, opaque variables
  • Code-Then-Execute / CaMeL: provenance-tracking interpreter + policies
  • Context-Minimization: drop unneeded context
  • Model-level: instruction hierarchy, spotlighting, Prompt Shields

Guardrails, harness & evals

Guardrails

  • Positions: input · context/retrieval · dialog · action/tool · output
  • Deterministic (schemas, allowlists, OPA) for guarantees; classifiers (Prompt Shields, Llama Guard) for risk reduction
  • Implemented as middleware: Agents SDK guardrails, LangChain middleware, SK filters, Claude Code hooks, NeMo rails
  • Fail closed, generic refusals, log every decision
  • Tune with recall, FPR, precision, latency; shadow mode first

Agent harness

  • Agent = model + harness (loop, context, tools, permissions, hooks, sandbox, memory, telemetry)
  • Defaults: read-only, ask before write/exec/network, deny secrets
  • Narrow typed tools; identity from the session, never the model
  • Budgets: steps, tokens, time, money; checkpoints for rollback
  • Protect harness config from the agent (CurXecute lesson)

Eval harness

  • Dataset → runner (N trials) → system → scorers → aggregate → gate
  • Record: model version, prompt hash, temperature, seed, N, dataset/judge versions, guardrail config
  • Report ASR with utility and over-refusal
  • LLM judge: binary rubric, different model family, Cohen's κ vs humans
  • Tools: lm-eval-harness, Inspect, promptfoo, RAGAS, DeepEval

30-second answers

"Biggest risk in LLM apps?"Indirect prompt injection combined with excessive agency. Untrusted content steers a model that holds real permissions. Fix it with containment: least privilege, user-scoped tokens, deterministic authZ, egress control, HITL.
"How do you secure RAG?"Enforce document permissions at retrieval (pre-filter from the authenticated identity plus a live check), isolate tenants, scan and spotlight retrieved content, keep the bot read-only, add groundedness and DLP on output, and test with canary docs.
"How do you secure agents?"Check the lethal trifecta. Give agents identity and OBO tokens, put a tool gateway with policy-as-code in front of tools, sandbox execution, segment memory, use risk-tiered HITL, add budgets and circuit breakers, log everything, and keep a kill switch.
"MCP risks?"Tool poisoning, rug pulls, tool shadowing, injection via results, token theft and passthrough, local server RCE, and over-scoped tokens. Use an allowlist registry, pin and hash definitions, sandbox, OAuth 2.1 with no passthrough, and a gateway with logging.
"OWASP vs ATLAS vs NIST?"OWASP says what can go wrong (builders). ATLAS says how attackers do it (red team and SOC). NIST AI RMF says how to govern risk (leadership).
"What is PyRIT?"Microsoft's open-source GenAI red-team automation: targets, attacks (single and multi-turn, e.g. Crescendo and TAP), converters, scorers and memory. It scales attacks so humans can focus on creative and business-logic abuse.
"Is prompt injection solvable?"Not at the model level today. Treat it as a design constraint: limit the blast radius, use injection-resistant patterns (plan-then-execute, dual LLM, CaMeL), and layer classifiers to lower the rate.
"How do you design guardrails?"Five rail positions (input, context, dialog, action, output). Deterministic rails for must-never-happen rules, classifiers to reduce risk. Implement as middleware, fail closed, log decisions, tune on real traffic with recall and FPR.
"What would you measure?"ASR per attack class and channel, leakage canaries, unauthorized actions, plus task success, over-refusal, faithfulness, latency and cost. N trials, Wilson CIs, pass^k for agents, gates in CI.
"What is harness engineering?"Designing the runtime around the model (loop, context, tools, permissions, hooks, sandbox, telemetry) so security guarantees hold even when the model is hijacked.
"First 90 days?"Inventory (including shadow AI), policy and intake, risk-tier, reference architectures, threat model and red-team top systems, CI evals, monitoring and IR, training, aligned to NIST AI RMF.
