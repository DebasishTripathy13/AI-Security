Module 02 · Classic AppSec

OWASP Top 10 (Web 2021 & 2025) and API Security Top 10 (2023)

AI apps are still web apps and APIs. Interviewers check that you know the classic lists and can explain how each risk comes back through an LLM or agent.

⏱ 25 minPriority ★★
Key takeaways
  • 2025 list: Broken Access Control stays #1 and absorbs SSRF; new entries are Software Supply Chain Failures (A03) and Mishandling of Exceptional Conditions (A10).
  • API Top 10 (2023) is led by BOLA, which agents reproduce whenever the model chooses object IDs.
  • Every classic vulnerability has an AI path: output → XSS/SQLi/RCE, fetch tools → SSRF, pickled models → insecure deserialization.
  • Treat the LLM as an untrusted user inside your network.

What the OWASP Top 10 is

  • An awareness document listing the most critical web application security risk categories, based on contributed vulnerability data (CWE incidence) plus a community survey for emerging risks.
  • Editions: 2003, 2004, 2007, 2010, 2013, 2017, 2021 and 2025. Many teams and job descriptions still quote 2021, so know both.
  • It isn't a standard. For verifiable requirements, cite OWASP ASVS (Application Security Verification Standard). For program maturity, cite OWASP SAMM.
  • The GenAI lists (LLM Top 10, Agentic Top 10) come from the OWASP GenAI Security Project.

Category deep dives (2025 order, with the AI angle)

A01:2025

Broken Access Control

2021: A01 + A10 SSRF

Users or systems act outside their intended permissions: reading other users' data, calling admin functions, or making the server request internal resources.

Examples

  • IDOR: /invoice?id=1002 returns someone else's invoice
  • Missing function-level checks (user can call /admin/*)
  • JWT/cookie tampering, CORS misconfig, force browsing
  • SSRF: server fetches http://169.254.169.254/ (cloud metadata), as in the Capital One 2019 breach

Prevention

  • Deny by default; enforce server-side in one central authZ layer
  • Check object ownership on every request; use unguessable IDs as defense in depth only
  • SSRF: allowlist destinations, block private/link-local ranges, disable redirects, use IMDSv2, segment the network
  • Log and alert on access-control failures; rate limit
AI angleAn agent tool like get_order(order_id) where the LLM supplies the ID is BOLA via the model, so the tool must check ownership against the user's identity. RAG without document ACLs is broken access control. A "browse URL" or "fetch" tool is an SSRF primitive that prompt injection can aim at metadata endpoints.
A02:2025

Security Misconfiguration

2021: A05

Insecure defaults, missing hardening, unnecessary features, verbose errors, open cloud storage, or permissive headers. XXE is part of this category.

Examples

  • Default admin credentials; directory listing; stack traces to users
  • Public S3/Blob buckets; permissive CORS; missing security headers
  • XML parsers with external entities enabled (XXE)

Prevention

  • Repeatable hardening (IaC + policy-as-code), minimal platforms
  • Automated configuration scanning (CSPM), environment parity
  • Segmented architecture; security headers; disable unused features
AI angleInternet-exposed Jupyter, Ray, MLflow, Ollama, or vector DBs with no auth. ShadowRay (2023–24) exploited the unauthenticated Ray Jobs API (CVE-2023-48022) on AI clusters. LLM gateways left in debug mode can leak prompts and keys.
A03:2025

Software Supply Chain Failures

2021: A06 (broadened)

Compromise or weakness anywhere in the chain of dependencies, build systems, CI/CD and distribution infrastructure, not just "outdated libraries".

Examples

  • SolarWinds (build compromise), Log4Shell (vulnerable dependency)
  • xz-utils backdoor (2024, malicious maintainer)
  • Dependency confusion, typosquatting, self-propagating npm worms (e.g. "Shai-Hulud", 2025)

Prevention

  • SBOM + SCA; pin versions and verify hashes/signatures (Sigstore)
  • SLSA build provenance; hardened, least-privilege CI tokens
  • Private registries/mirrors; review new dependencies; patch SLAs
AI angleModels, datasets, LoRA adapters, prompt templates, plugins and MCP servers are all supply chain (LLM03, ASI04). Pickled models execute code on load. LLMs hallucinate package names that attackers then register ("slopsquatting"). Use an AI-BOM and model signing.
A04:2025

Cryptographic Failures

2021: A02

Failures in protecting data in transit and at rest: weak or no encryption, poor key management, weak randomness, unsalted fast password hashes.

Examples

  • HTTP or TLS 1.0; MD5/SHA-1 passwords; ECB mode
  • Hard-coded keys; keys in Git; predictable tokens

Prevention

  • Classify data; encrypt sensitive data at rest and in transit (TLS 1.2+/1.3)
  • AES-GCM / ChaCha20-Poly1305; Argon2id/bcrypt/scrypt for passwords
  • KMS/HSM, key rotation, secrets managers; CSPRNG
AI angleAPI keys pasted into system prompts or notebooks; prompt and response logs with PII stored in plaintext; embeddings stored unencrypted even though they can be inverted back to text.
A05:2025

Injection

2021: A03

Untrusted data is sent to an interpreter as part of a command or query: SQL, NoSQL, OS command, LDAP, template/EL injection, and XSS.

Examples

  • "SELECT * FROM users WHERE id = '" + id + "'"
  • Shell: os.system("ping " + host)
  • Reflected, stored and DOM XSS; SSTI in Jinja2

Prevention

  • Parameterized queries / safe APIs / ORMs
  • Server-side allowlist validation; context-aware output encoding
  • CSP for XSS; least-privileged DB accounts
AI anglePrompt injection is injection into a natural-language interpreter, but with no parameterization available. LLM output flowing into SQL (text-to-SQL), a shell, eval or HTML is classic injection with the model as the delivery mechanism (LLM05 Improper Output Handling).
A06:2025

Insecure Design

2021: A04

Missing or ineffective security controls by design, as opposed to implementation bugs. A perfect implementation of an insecure design is still insecure.

Examples

  • Password recovery via "security questions"
  • No rate limiting on a business flow (ticket scalping)
  • Trusting client-side checks

Prevention

  • Threat modeling in design; abuse/misuse cases
  • Secure design patterns and reference architectures
  • Secure SDLC with AppSec involvement; tiered segregation
AI angleLetting the LLM make authorization decisions; building an agent that combines private data, untrusted input and outbound communication (the lethal trifecta); no HITL on irreversible actions. These are design flaws that no guardrail fixes.
A07:2025

Authentication Failures

2021: A07 Identification & Auth.

Weaknesses in confirming identity and managing sessions.

Examples

  • Credential stuffing; no MFA; weak or default passwords
  • Session fixation; session IDs in URLs; no logout invalidation

Prevention

  • MFA / passkeys (FIDO2); breached-password checks
  • Rate limiting and lockout with care; secure session management
AI angleNon-human identity sprawl: agents with long-lived API keys, shared service accounts, MCP servers with no authentication, tokens stored in agent memory or config files. Agents need their own identities and short-lived, audience-bound tokens.
A08:2025

Software or Data Integrity Failures

2021: A08

Code and infrastructure that don't protect against integrity violations: insecure deserialization, unsigned updates, untrusted CI/CD pipelines, untrusted CDNs.

Examples

  • Java/Python native deserialization of untrusted data → RCE
  • Auto-update without signature verification
  • Scripts from a CDN without Subresource Integrity

Prevention

  • Digital signatures; SRI; verify integrity before use
  • Avoid native deserialization of untrusted data; use JSON with schemas
  • Protected CI/CD with code review and separation of duties
AI angleA pickled PyTorch model is insecure deserialization: torch.load() on an untrusted .pt/.bin can execute code. Use safetensors or weights_only=True, scan with ModelScan, and sign models. Poisoned datasets are data-integrity failures.
A09:2025

Security Logging & Alerting Failures

2021: A09

Insufficient logging, monitoring and alerting to detect and respond to breaches.

Examples

  • Login failures not logged; logs only local; no alert thresholds
  • Log injection; sensitive data written to logs

Prevention

  • Log security events with context; centralize (SIEM); tamper-evident storage
  • Alerting with tested thresholds; incident response plan (NIST SP 800-61)
AI angleLog prompts, retrieved chunk IDs, tool calls, approvals and model versions, with PII redaction. Without these you cannot reconstruct a prompt-injection incident. Alert on injection-classifier hits, unusual tool sequences, spend spikes and egress to new domains.
A10:2025

Mishandling of Exceptional Conditions

New in 2025

Improper handling of errors and abnormal states: failing open, unchecked return values, information-leaking errors, inconsistent state after partial failures.

Examples

  • Auth service times out, so the app lets the request through (fail open)
  • Stack traces revealing internals; partial transactions not rolled back
  • Race conditions in error paths

Prevention

  • Fail closed / secure defaults; centralized exception handling
  • Atomic transactions with rollback; generic user-facing errors
  • Test error paths and timeouts explicitly (chaos / fault injection)
AI angleThe content-safety API times out and the app sends the unfiltered prompt anyway. The model returns malformed JSON and a "lenient" parser falls back to executing raw text. Tool error messages are fed back into the context, where an attacker can plant instructions in them.

Interview soundbite"I treat the LLM as an untrusted user sitting inside my network. Anything it outputs gets the same validation I'd apply to input from the internet, and every tool it can call enforces authorization with the end user's identity."
